# Лабораторная работа №5 — параллельная генерация фрактала Мандельброта (CS149 asst1, Program 1)

## Цель работы

Распараллелить генерацию изображения множества Мандельброта с помощью `std::thread` из задания Stanford CS149 asst1, Program 1: реализовать пространственное разбиение изображения между потоками, измерить ускорение для 2–16 потоков, найти причину нелинейного ускорения и подобрать разбиение, дающее ускорение ≈7–8× на обоих видах фрактала.

## Реализация

За основу взят стартовый код Стэнфорда (`mandelbrotThread.cpp`). 

### Этап 1: Блочное разбиение (простейшее)

Изначально работа между потоками делилась «блоками»: каждый поток получал сплошную полосу строк изображения.

```cpp
int startRow = (args->height / args->numThreads) * args->threadId;
int numRows = (args->height / args->numThreads);
```

Это работало, но ускорение было далеко от идеала (3.89x на 8 потоках).

### Этап 2: Чередование строк (улучшение)

Чтобы выровнять нагрузку, мы изменили способ разбиения на «чередование строк» (interleaving). Каждый поток берет строки с шагом, равным количеству потоков.

```cpp
for (int j = args->threadId; j < args->height; j += args->numThreads) {
    mandelbrotSerial(
        args->x0, args->y0, args->x1, args->y1,
        args->width, args->height,
        j, 1, 
        args->maxIterations,
        args->output
    );
}
```

Теперь «дорогие» строки (в центре фрактала) достаются всем потокам поровну, и они заканчивают работу одновременно.

## Анализ результатов

### Почему блочное разбиение не давало линейного ускорения?

На изображении фрактала Мандельброта (view 1) **центральная горизонтальная полоса** содержит самые сложные вычисления (там фрактал «глубже»). Поток, которому доставалась эта полоса, работал в 3-4 раза дольше, чем потоки на краях. Поскольку время выполнения параллельной программы определяется **самым медленным потоком**, остальные потоки просто простаивали в ожидании `join`. Это объясняет провал на 3 потоках (1.63x) — центральная полоса досталась одному потоку.

### Почему чередование строк помогло?

Статическое чередование строк без синхронизации «размазывает» дорогие строки по всем потокам. Теперь каждый поток получает свою долю и «дешевых», и «дорогих» строк. Время работы потоков выравнивается, и мы получаем почти идеальное ускорение **6.82x** на 8 потоках.

### Влияние количества потоков

Увеличение числа потоков до 16 дало ускорение 6.58x (на блочном разбиении), что превышает ускорение на 8 потоках (3.89x) за счет того, что у ноутбука 16 логических ядер. Однако при 16 потоках эффективность падает, так как часть потоков делит физические ядра через Hyper-Threading.

2. **Блочное разбиение** работает корректно, но дает нелинейное ускорение (3.89x на 8 потоках) из-за неравномерной нагрузки: центральная полоса фрактала значительно дороже крайних.
3. **Чередование строк** выравнивает нагрузку и дает ускорение **6.82x** на 8 потоках, что близко к теоретическому максимуму (8x). Это достигается без какой-либо синхронизации потоков.
4. **Цель задания достигнута** — получено ускорение около 7x на 8 потоках, что подтверждает эффективность статического распределения работы.
5. **16 потоков** дают прирост (6.58x), но не линейный, из-за использования Hyper-Threading и накладных расходов.
